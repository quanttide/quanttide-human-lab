# p02 绩效观测工具 — 实验方案

## 实验目的

验证「意义从事后观测中浮现」：不做事前清单，只看实际产出 + 周期回看，创始人能否读出自己工作的主线与意义。

## 背景

意图仓绩效模块（`data/intention/performance/founder.md`）记录了绩效制度的演化：2025 年判例是事前清单 + 考核（清单已收入制度史 `data/history/performance/founder.md`）；2026 年进化为观测工具——创始人每天做一堆事，事前说不出每件事的意义，绩效改为如实记录每天的工作，意义从事后的观测里逐渐浮现。观测让工作先被看见，看见是考核的前提。

本实验验证这个进化方向是否真的成立：观测能不能替代事前断言，把意义找回来。

观测的数据源是实际产出，不是自我报告。创始人的产出目前主要集中在 GitHub——个人账号与 quanttide 组织下的提交、PR、发布、新建仓库，产出留痕天然存在，观测不需要任何额外的记录流程。

## 实验假设

1. 每日事务如实记录后，按周期回看能识别出重复出现的工作主题，主线可以从事后数据里读出来，不需要事前定义
2. 「说不清意义」的事务占比是可测量的，不是一个模糊感受——观测能把意义缺位定位到具体条目
3. 事后读出的意义可以转化为下个周期的事前判断：观测 → 意义 → 新的清单，闭环成立

## 实验设计

### 阶段 1：产出基线（第 1 周）

不新建记录流程，数据源直接用 GitHub 产出：取最近一周内个人账号与 quanttide 组织的提交、PR、发布、新建仓库，逐条拆成产出条目，每条标注：

| 字段 | 说明 |
|------|------|
| 日期 | 提交/合并/发布的当天 |
| 归属 | 属于哪个仓库/项目，据此推断类型（业务、体系、写作、培养） |
| 结果 | merged / released / 仅提交未闭环 |
| 意义 | 事前能否一句话说清为什么做（能/不能 + 原话） |

### 阶段 2：观测回看（第 2 周）

对一周的产出条目做三件事：

1. 按类型聚类统计，看哪几类事占了大部分时间
2. 找出重复出现但没有结果的事务——做了很多次、没有闭环的事
3. 找出「意义」栏大面积空白的类型——事前说不出为什么做的事集中在哪一类

### 阶段 3：意义读出（第 2 周末）

用观测数据回答三个问题，写成一页纸：

1. 这一周我的主线是什么？（从数据归纳，不凭印象）
2. 哪些事在观测里反复出现，但我从没断言过它的意义？
3. 哪些事观测证明它不值得做？

### 阶段 4：闭环验证（下一季度）

把读出的意义写成下季度的事前清单，交 HR 考核，季度末对账：观测数据支撑的事前断言，比拍脑袋的断言更准吗？

## 评价标准

| 指标 | 合格线 |
|------|--------|
| 从一周记录归纳出的主线数量 | ≤ 3 条，且每条能用数据指回具体产出条目 |
| 「反复做但意义未断言」的事 | 至少指出 1 件 |
| 阶段 3 的意义陈述 | 被下季度清单采纳，且季度末可对账 |

## 原型实现

首轮不写代码：阶段 1–3 手工完成，先验证观测本身有没有价值。只有手工回看被证明有效、且每周回看成本过高时，才做「日志 → 事务条目 → 聚类统计」的脚本或观测面板。

## 实验记录

每次回看后在本目录追加记录：

- 产出条目数量与分类分布
- 读出的主线与依据
- 发现的「意义空白」条目
- 对实验设计的调整

> 注意：实验记录可能涉及私有仓库的产出，入仓前必须脱敏（规则见根仓 AGENTS.md），只留方法、统计和结论，不留带业务细节的原始条目。
